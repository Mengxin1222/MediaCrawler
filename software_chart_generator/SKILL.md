# Software Chart Generator

## 核心能力

对源码进行结构化分析，使用Mermaid语法生成6种软件开发标准图表，并保存为可渲染的Markdown文件。

## 两种工作模式

### 普通模式（单张图）

**触发条件**：用户输入 `/software-chart-generator [图类型] [路径]`

**行为**：针对指定范围生成**一张**对应类型的图表，包含完整解释说明

### 深度模式（多张图）

**触发条件**：用户输入 `/software-chart-generator [图类型] [路径]` 且消息中包含 "深度画一下"、"deep mode"、"深度模式"、"详细画" 等关键词

**行为**：
- 一类图生成**多张**，层层递进
- 例如模块图：先画整体模块 → 再为每个核心模块画详细模块图 → 最后画模块依赖关系图
- 每张图都有独立解释
- 参考 `references/` 目录下的示例文件了解深度模式输出标准

## 支持的图类型

| 类型关键词 | 中文关键词 | 说明 |
|-----------|-----------|------|
| `sequence` | 时序图 | 对象间交互时间顺序 |
| `usecase` | 用例图 | 系统功能与用户角色关系 |
| `er` / `dataflow` | 数据流E-R图 / E-R图 | 数据流动与实体关系 |
| `architecture` | 系统架构图 | 分层架构与技术栈 |
| `business` | 业务流程图 | 业务操作执行流程 |
| `module` | 模块结构图 | 代码模块组织与依赖 |
| `all` | 全部 | 生成所有6种图（深度模式下每种多张） |

## 工作流程

### 1. 解析用户输入

提取：
- **模式**：普通 or 深度（检测 "深度画一下" / "deep" 等关键词）
- **图类型**：从关键词映射到6种类型之一
- **源码路径**：GitHub URL 或本地路径（默认当前目录）

### 2. 源码分析

使用工具分析源码：
- `Glob` / `LS`：扫描项目结构
- `Read`：读取核心文件（入口、配置、模型）
- `Grep` / `SearchCodebase`：分析依赖关系、类继承、数据流
- 识别：入口文件、核心模块、数据库模型、API接口、用户角色、业务流程

### 3. 图表生成

根据图类型选择Mermaid语法，按以下策略生成：

**时序图**：识别Actor/Participant → 按时间顺序排列消息 → 标注alt/opt/loop条件分支
**用例图**：识别Actor角色 → 识别UseCase功能 → 标注include/extend关系 → 按模块分组
**数据流E-R图**：识别外部实体/处理过程/数据存储 → 构建DFD → 识别实体属性关系 → 构建E-R
**系统架构图**：按层次分组（表示/应用/业务/数据）→ 标注技术栈 → 展示调用关系
**业务流程图**：识别开始结束节点 → 排列处理步骤 → 标注判断分支 → 识别循环
**模块结构图**：按目录层级展示 → 标注模块职责 → 展示import依赖 → 识别核心/公共模块

### 4. 深度模式的多图策略

#### 模块结构图（深度）
1. **整体模块图**：顶层目录结构，主要模块划分
2. **核心模块详细图**：为每个核心模块（如核心业务、数据层、工具层）生成详细图
3. **模块依赖关系图**：展示模块间的调用/导入关系

#### 系统架构图（深度）
1. **高层架构图**：分层架构和主要技术栈
2. **详细组件图**：为每层生成内部组件图
3. **部署架构图**：部署拓扑和外部依赖

#### 时序图（深度）
1. **主流程时序图**：核心业务流程的完整交互
2. **子流程时序图**：关键子流程（如登录、支付、数据同步）
3. **异常处理时序图**：错误处理和降级流程

#### 其他类型（深度）
- **用例图**：按用户角色分组，每个角色一张
- **业务流程图**：按业务域分组，每个域一张
- **数据流E-R图**：先整体数据流，再详细E-R，最后数据字典

### 5. 图表解释规范

每张图必须包含以下解释（保存为Markdown）：

    # [项目名] [图类型] ([图类型英文])

    ## 1. [子图标题]

    ```mermaid
    [图表内容]
    ```

    ### 图表解释

    #### 1. 概述
    [这张图展示的是什么，解决什么问题]

    #### 2. 关键元素说明
    - **元素A**：职责、作用、为什么存在
    - **元素B**：职责、作用、为什么存在

    #### 3. 关键流程/关系说明
    - **流程A**：详细执行步骤和数据变化

    #### 4. 设计亮点
    [架构上的重要设计选择及其原因]

    #### 5. 使用建议
    [如何阅读这张图，适用场景]

    ---

    ## 2. [子图标题]

    ```mermaid
    [图表内容]
    ```

    ### 图表解释
    ...

    ---

    ## N. [子图标题]
    ...

    ---
    *生成时间: [日期]*
    *模式: [普通/深度]*
    *所属项目: [项目名]*
    *文件包含: [N] 张图*

### 6. 输出规范

#### 6.1 文件组织方式

**普通模式**：一类图一个文件，文件内包含一张图及其解释

**深度模式**：一类图一个文件，文件内包含**多张图**，用二级标题 `##` 分隔

    [项目名]-charts/
    ├── 01-sequence-diagram.md            # 时序图：包含多张时序图
    ├── 02-use-case-diagram.md            # 用例图：包含多张用例图
    ├── 03-data-flow-er-diagram.md        # 数据流E-R图：包含多张图
    ├── 04-system-architecture.md         # 系统架构图：包含多张架构图
    ├── 05-business-process.md            # 业务流程图：包含多张流程图
    ├── 06-module-structure.md            # 模块结构图：包含多张模块图
    └── ...

#### 6.2 文件命名规范

**格式**：`[序号]-[图类型英文].md`

| 序号 | 文件名 | 说明 |
|------|--------|------|
| 01 | `01-sequence-diagram.md` | 时序图 |
| 02 | `02-use-case-diagram.md` | 用例图 |
| 03 | `03-data-flow-er-diagram.md` | 数据流E-R图 |
| 04 | `04-system-architecture.md` | 系统架构图 |
| 05 | `05-business-process.md` | 业务流程图 |
| 06 | `06-module-structure.md` | 模块结构图 |

## Rules

1. **必须分析源码**：不能凭空生成，必须基于实际代码结构
2. **必须提供解释**：每张图必须有对应的5部分文字解释
3. **标准Mermaid语法**：确保可在GitHub/GitLab/VS Code中渲染
4. **中文标签**：图表中的说明用中文，代码中的类名/函数名保留英文
5. **清晰可读**：节点命名简洁，避免过度拥挤
6. **保存为.md**：所有输出保存为Markdown文件
7. **深度模式递进**：多张图之间要有逻辑递进关系，从整体到细节
8. **GitHub源码**：如用户提供GitHub URL，先克隆或读取关键文件再分析
